1. The problem with the existing approach

Standard YOLO + ByteTrack follows a person by an ID number. It has no memory of what the person looks like, so it fails when (a) the person is hidden and comes back with a new ID, (b) two people cross and the tracker swaps their IDs, or (c) a person who looks similar appears nearby. The system then follows the wrong person or gives up.

2. What is new in this project

  • Target state machine (IDLE, ACQUIRED, OCCLUDED, REACQUIRING, LOST) with click-to-select.
  • Occlusion-type reasoning – works out why the person vanished (left the frame / hidden by a person / hidden by an object) and searches accordingly.
  • Identity verification – checks every frame that the tracked box is still the same person and corrects ID swaps when people cross.
  • Multi-cue reacquisition – predicted position + upper/lower-body colour + size + confidence, with weights that shift towards appearance the longer the person is hidden.
  • Ambiguity handling – if two candidates look equally likely, it waits instead of guessing.
  • Quality-gated appearance memory – learns the person's look only when clearly visible, so it is never polluted by someone else.
  • Wide-search recovery – after long occlusions it keeps looking instead of giving up.
  • Real-time – works on video files, webcam and IP-camera streams.

3. How it was compared

All three systems receive exactly the same detections from YOLO11n + ByteTrack, so the only difference is the target-management logic. The true target was marked by hand in sampled frames (ground truth). Existing = follow the clicked ID only. + Our reacquisition = appearance memory, ambiguity handling, identity verification, wide search. Ours = all of that plus occlusion-type reasoning.

6. Limitations (honest analysis)

  • Colour-based appearance fails if several people wear nearly identical clothes; a ReID neural embedding would be the next step.
  • Thresholds are hand-tuned for the recorded scenes.
  • Re-acquisition after a long absence can take longer than the baseline, because the system refuses implausible candidates and waits for a confident match.
  • One selected target at a time; a moving camera would need camera-motion compensation.
